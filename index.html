Approach

Three rules I don't break.

  1. 01
    Baselines, not anecdotes. Every result ships with the baseline it beat and the hardware it ran on. A speedup without its baseline is a story, not a measurement.
  2. 02
    Verification is the product. An agent that grades its own work will learn to cheat the grader. Most of the engineering goes into making that structurally impossible.
  3. 03
    Consumer hardware first. If a method needs an H100 cluster, the method hasn't been found yet. Six gigabytes is the constraint I design against.

KARMA

Five LLM agents that write, verify, and iterate on GPU kernels — and cannot lie about the result.

A five-agent pipeline — classifier → planner → coder → verifier → reflector — under hardware-grounded prompting. The interesting problem was never generating kernels; it was trusting them.

So the loop is closed: compile → three-seed correctness → determinism gate → interleaved benchmarking. An agent cannot pass by gaming the benchmark, which is why the false-positive rate is zero rather than low.

A RAG memory over ChromaDB carries technique between tasks. One authored entry moved the agent from 0.26× to 1.09× on an identical task — in-context learning you can measure across runs. Results that prior work needed H100 clusters to reach, on a 6 GB card.

02 · Systems

Repliq

A screen recording becomes an executable workflow. A ReAct agent runs it without ever holding a secret.

You demonstrate a task once. The agent reasons about what it saw, acts through real tools, observes the result, and repeats — the Reason–Act–Observe loop, made production-grade.

The tool layer is MCP-compatible, with full execution tracing, retry and error handling, and async orchestration through FastAPI. Credentials live in a zero-trust vault — Fernet-encrypted, fronted by OAuth 2.0 — so a sandboxed agent never touches a long-lived secret, even mid-run.
